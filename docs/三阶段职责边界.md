> `legasynth_orchestrator` 位于三阶段之上，只负责按冻结接口启动各阶段、检查产物与记录状态；它不拥有故事规划、MIDI 生成、心跳时序或音频渲染规则，也不得绕过任何阶段验证。

> 它消费 Stage 1 的 `stage2_plan.json`，生成并保护完整心跳 MIDI 事件，
> 最终 MIDI 与哈希清单交给 Stage 3。固定结构无法匹配计划时必须拒绝运行。

> 2026-07-21：Stage 1 测试模式调整为 48 小节 `A-B-A`，每段均为

> Stage 3 不写死曲式或总小节数，直接按 Stage 2 完整 MIDI 的时间轴渲染。

## Stage 1：规划、心音素材准备与主题动机生成

Stage 1 包含故事规划链、MuseCoco 主题链和心音素材链。

职责：

1. Story Agent 分析故事、情绪和张力，决定曲式、段落长度、BPM、拍号、调性、主题家族、鼓轨节奏型及 MIDI-GPT 保护/编辑范围。
2. 生成 MuseCoco 自然语言提示、12类结构化属性和官方60分类头直接编码。
3. 调用 MuseCoco 生成每个主题家族的动机 MIDI。
4. 在 Stage 1 内完成 MuseCoco MIDI 后处理：
   - 强制统一到计划 BPM；
   - 强制统一到计划主音和调式；
   - 调整或严格校验为要求的小节长度；
   - 记录处理前后文件哈希和校验结果。
5. 从原始心音 WAV 提取、筛选并封装真实 S1/S2 音色素材，供最终 MIDI 渲染时使用。
6. 向 Stage 2 交付已经处理完成的主题动机、曲式结构、逐段鼓轨指令和 MIDI-GPT 可编辑范围。

MuseCoco 生成主题以及主题 MIDI 的速度、调性、小节长度修正都属于 Stage 1，不属于 Stage 2。

## Stage 2：完整多轨 MIDI 构建与 MIDI-GPT 补全

职责：

1. 按 Stage 1 的曲式、小节坐标和段落长度放置已经处理完成的主题动机。
2. 按 Agent 的逐段鼓轨指令生成完整歌曲的心跳鼓轨。
3. 将心跳鼓轨写入完整多轨 MIDI，并作为需要保护的结构轨道。
4. 构建 MIDI-GPT 所需上下文，只开放计划允许修改的旋律、和声、低音、伴奏、过渡和延伸区域。
5. 调用 MIDI-GPT 完成允许区域，并校验固定主题和心跳鼓轨未被破坏。
6. 输出已经包含心跳鼓轨的完整多轨 MIDI。
7. 发布 `stage3_handoff.json`，冻结完整 MIDI、Stage 3 render plan 和 Stage 1 heartbeat package 清单的路径及哈希。
8. 可按用户显式选择，在发布前执行两小节整体音高织体重复检测；`detect` 只审计，`regenerate` 只在计划允许编辑的小节内局部调用 MIDI-GPT。该检查不区分旋律与和声、不惩罚固定节奏，并必须保持受保护主题和心跳轨不变。

Stage 2 生成的是 MIDI 鼓轨，不在此阶段混合最终音频。Stage 2 不重新决定故事结构，也不重新调用规划 LLM。

## Stage 3：完整 MIDI 的统一渲染与混音

Stage 3 的输入是 Stage 2 已经完成的整首多轨 MIDI；心跳鼓轨此时已经存在。
它必须支持 48 小节测试曲式以及正式模式产生的其他合规长度，不得依赖旧的 32 小节或 8/16/8 假设。

职责：

1. 为普通音乐轨分配对应乐器音源。
2. 为既有心跳鼓轨分配 Stage 1 准备的真实心音音色、采样映射或 SoundFont。
3. 将完整 MIDI 的所有轨道作为一个整体进行渲染和混音。
4. 完成整体音量、峰值、声像及必要的最终输出处理。
5. 输出最终音乐音频及混音审计信息。

Stage 3 不负责：

- 重新生成心跳鼓轨；
- 重新解析故事或规划 S1/S2 节奏；
- 再次调用 MuseCoco 或 MIDI-GPT；
- 把“心跳 WAV”和“主音乐 WAV”作为两个独立成品再自动叠加。

## 冻结的数据流

```text
Stage 1
故事规划 + 心音素材准备 + MuseCoco主题生成 + 主题MIDI速度/调性/长度修正
    ↓
Stage 2
曲式装配 + 完整心跳鼓轨生成 + MIDI-GPT补全 + 完整多轨MIDI
    ↓
Stage 3
为完整MIDI分配音源并统一渲染混音
```

## 对现有实现的影响

- `stage1_story_agent` 的 MuseCoco 编码、速度修正和主音修正属于 Stage 1。
- MuseCoco 小节长度调整仍需在 Stage 1 完成并验证。
- `stage1_story_agent/stage2_plan.json` 是 Stage 2 生成心跳鼓轨和控制 MIDI-GPT 编辑范围的主要计划输入。
- `midigpt_scaffold_builder` 应迁移为直接消费当前 Agent 交付，并在 Stage 2 输出完整心跳鼓轨。
- `heartbeat_post_renderer` 所代表的“在 MIDI-GPT 后重新读取鼓轨并生成心跳轨”不属于正式流程；该实验实现不得作为 Stage 3 入口。
