# MuseCoco 直接编码规则

## 1. 文档目的

本文记录第一阶段故事 Agent 将 DeepSeek 的结构化属性输出直接转换为 MuseCoco 编码时必须遵守的规则。该规则已由 `stage1_story_agent/musecoco_encoder.py` 实现，并在每次成功规划后导出 `predict_attributes.json` 等五个直接编码文件。

## 2. 核心要求：已知字段采用封闭世界编码

当 DeepSeek 已经输出某个属性字段，并且该字段的状态不是“未知”时，该字段视为信息完整的确定性选择：

- DeepSeek 明确选择的选项编码为“使用/是”；
- 同一字段内没有被选择的其他选项编码为“硬性不使用/否”；
- 不得把同一已知字段的未选选项编码为 `NA`；
- 只有整个字段缺失、明确为未知，或无法可靠判断时，才允许把该字段编码为 `NA`。

该规则属于本项目对 MuseCoco 直接编码的强制约束，优先于官方数据准备代码中“未提及选项默认设为 NA”的训练数据行为。

## 3. 多标签三态字段

本规则主要影响具有“是、否、NA”三态分类头的多标签字段：

- `I1s2`：28 个乐器分类头；
- `S4`：22 个流派分类头。

每个展开分类头的编码含义为：

```text
[1, 0, 0] = 使用/是
[0, 1, 0] = 硬性不使用/否
[0, 0, 1] = 未知/NA
```

### 3.1 已知乐器字段

DeepSeek 输出：

```json
{
  "I1s2": ["violin"]
}
```

必须编码为：

```text
I1s2_violin = [1, 0, 0]
其余 27 个 I1s2_* 分类头 = [0, 1, 0]
```

其余乐器不得编码为 `[0, 0, 1]`，因为 `I1s2` 已经是已知字段；此时列表表示完整的允许乐器集合，而不是不完整的举例。

DeepSeek 输出多个乐器时同理：

```json
{
  "I1s2": ["piano", "cello"]
}
```

对应：

```text
I1s2_piano = [1, 0, 0]
I1s2_cello = [1, 0, 0]
其余 26 个 I1s2_* 分类头 = [0, 1, 0]
```

### 3.2 已知流派字段

DeepSeek 输出：

```json
{
  "S4": ["classical"]
}
```

必须编码为：

```text
S4_classical = [1, 0, 0]
其余 21 个 S4_* 分类头 = [0, 1, 0]
```

## 4. 未知字段

只有字段整体未知时，才使用 NA。未知必须由结构化状态表达，不能仅通过空字符串或任意自然语言猜测。

未来直接编码接口应至少接受以下一种明确表示：

```json
{
  "I1s2": null
}
```

或：

```json
{
  "I1s2": {
    "status": "unknown",
    "values": null
  }
}
```

若 `I1s2` 整体未知：

```text
全部 28 个 I1s2_* 分类头 = [0, 0, 1]
```

若 `S4` 整体未知：

```text
全部 22 个 S4_* 分类头 = [0, 0, 1]
```

空列表不得静默解释。编码器必须在接口设计中固定以下二者之一，并通过 Schema 表达：

- 禁止空列表，未知只能使用 `null/status=unknown`；或
- 明确定义空列表表示“已知为空”，此时所有选项均编码为硬性不使用。

本项目推荐第一种：禁止空列表，以避免把“未知”误编码为“全部禁止”。

## 5. 单选字段

`R1`、`R3`、`S2s1`、`B1s1`、`TS1s1`、`K1`、`T1s1`、`P4`、`EM1` 和 `TM1` 是单选分类向量，不为每个选项分别建立“是、否、NA”三态分类头。

当字段已知时：

- 被选择类别的位置为 `1`；
- 其他类别以及末尾 `NA` 位置均为 `0`。

例如：

```text
R3 = high  -> [0, 0, 1, 0]
K1 = minor -> [0, 1, 0]
EM1 = Q3   -> [0, 0, 1, 0, 0]
```

当整个字段未知时，只有末尾 `NA` 位置为 `1`：

```text
R3 = unknown  -> [0, 0, 0, 1]
K1 = unknown  -> [0, 0, 1]
EM1 = unknown -> [0, 0, 0, 0, 1]
```

对于单选向量，“其他选项硬性不使用”体现为其他类别位置为 `0`；不存在为每个未选类别额外输出 `[0, 1, 0]` 的结构。

## 6. 来源与审计

直接编码产物必须保存字段来源，至少区分：

```text
explicit   用户明确指定
llm        DeepSeek 根据故事判断
derived    Python 根据确定性规则派生
defaulted  项目默认值
unknown    无法确定
```

除 `unknown` 外，以上所有来源都属于“已知字段”，必须执行封闭世界编码规则。特别是：由 Python 派生或项目默认得到的字段不能编码成 NA。

## 7. 校验要求

直接编码器必须拒绝或报告以下情况：

- 已知的 `I1s2` 或 `S4` 中存在不受 MuseCoco 支持的值；
- 同一分类头同时被标记为使用和不使用；
- 已知字段中出现 NA 分类头；
- 未知字段中出现任何“使用”或“硬性不使用”分类头；
- 多标签字段为空列表但 Schema 没有明确规定空列表语义；
- 单选字段的向量不是严格 one-hot；
- 任意三态分类头不是 `[1,0,0]`、`[0,1,0]` 或 `[0,0,1]` 之一。

## 8. 必测案例

实现直接编码功能时至少加入以下测试：

1. `I1s2=[violin]`：violin 为“是”，其余 27 个乐器为“否”，不存在 NA。
2. `I1s2=[piano,cello]`：两个乐器为“是”，其余 26 个为“否”。
3. `S4=[classical]`：classical 为“是”，其余 21 个流派为“否”。
4. `I1s2=unknown`：28 个乐器全部为 NA。
5. `S4=unknown`：22 个流派全部为 NA。
6. 已知单选字段：选中类别为 1，NA 为 0。
7. 未知单选字段：仅 NA 为 1。
8. 不支持的乐器、流派或单选值必须在写出文件前失败。
