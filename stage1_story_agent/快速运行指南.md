# 第一阶段故事 Agent 快速运行指南

## 最短运行流程

在 PowerShell 中进入项目根目录：

```powershell
cd "<repository-root>"
```

第一次运行时，创建本地 Key 文件：

```powershell
Copy-Item .\.env.example .\.env
```

打开 `.env`：

```powershell
notepad .\.env
```

将其中的占位符替换为真实 DeepSeek Key，然后保存：

```dotenv
DEEPSEEK_API_KEY=你的真实DeepSeekKey
```

直接从命令行输入中文故事（其余请求字段使用默认值）：

```powershell
D:\conda\python.exe -m stage1_story_agent plan --story-text "这是一个需要转化为音乐结构的中文故事。" --force
```

默认生成的请求为 `story_id=cli-story`、`language=zh-CN`。正式模式先根据故事在 1–6 段之间决定曲式规模和主题复用关系，每段统一采用8小节主题加默认8小节填充，因此总长为16–96小节。MuseCoco 默认以约12小节为生成目标，最终交付严格统一为8小节。程序使用同一个本地时间戳前缀创建四个互相分离的目录，例如 `...-musecoco`、`...-heartbeat`、`...-stage2` 和 `...-audit`。

可分别调整生成目标和最终输出长度：

```powershell
D:\conda\python.exe -m stage1_story_agent plan `
  --story-text "这是一个需要转化为音乐结构的中文故事。" `
  --musecoco-generation-bars 12 `
  --musecoco-output-bars 8 `
  --force
```

`--musecoco-generation-bars` 必须不小于8。主题输出固定为8小节；`--musecoco-output-bars` 仅接受8。每段默认再开放8小节填充区。

固定 ABA 测试模式：

```powershell
D:\conda\python.exe -m stage1_story_agent plan --story-text "平静开始，冲突逐渐展开，最终回到最初的主题。" --test-mode
```

该模式固定为 C minor、96 BPM、4/4 和48小节 `A-B-A`。每段都是16小节：前8小节为主题动机，后8小节为 MIDI-GPT 填充区。MuseCoco 被鼓励生成约12小节，交付给 Stage 2 的主题动机统一为8小节。故事和心跳 WAV 可以自由替换；故事继续决定 A/B 主题的配器、风格、律动与逐段张力，Stage 2 再根据张力决定心跳密度。测试模式不会把 MuseCoco 旋律硬覆盖成固定钢琴/小提琴素材。三个段落都保护前8小节并开放后8小节。

在调用 LLM 时，Agent 也会把同一配置和 `musecoco-prompting-v4` 规则注入 Prompt，让模型原始输出本身优先选择清晰独奏乐器、集中音域和适中节奏。项目策略硬性禁用 Stravinsky 和 synthesizer；官方 60 头码表仍保留其位置以维持索引兼容，但任何正式计划或编码若选择它们都会校验失败。模型只评估叙事段的 `valence` 与 `tension`，EM1 由 Python 固定算法生成；即使旧式模型返回 Q4，该字段也只留在 raw audit，不会进入正式 MuseCoco 提示词。

最终 `musecoco_text` 不直接采用 LLM 的自由文本，而由 Python 按 `official-template-aligned-v1` 渲染。该风格仿照本地 MuseCoco 官方 `predict.json` 与模板文件，使用 `This music is composed in...`、`The music is in the vein of...`、`The music conveys...` 等自然陈述句，完整覆盖 12 类属性。精确 BPM 和主音只保留在 JSON 结构化字段中；提示词使用 MuseCoco 支持的 `slow/moderate/fast` 与 `major/minor` 类别。

使用 JSON 文件运行完整故事 Agent，并自动入队、运行 MuseCoco、收集及归一化结果：

```powershell
D:\conda\python.exe -m stage1_story_agent plan `
  --input ".\stage1_story_agent\examples\story_input.example.json" `
  --output-dir ".\stage1_story_agent\outputs\story-001" `
  --enqueue-musecoco `
  --run-musecoco-queue `
  --force
```

MuseCoco 原始 MIDI 超过输出目标时，会按 `output_bars × 拍号 × PPQ` 的精确结束 tick 裁剪，并为边界处仍发声的音符补 Note Off。原始 MIDI 短于目标时立即报错，不延长 End-of-Track、不补静音，也不发布半成品。成功后的每个主题位于 `generated_themes/<theme_family_id>/final.mid`，依次完成小节、速度和调性处理。默认调性软控制在检测可靠时统一计划调性，不可靠时保留原调并记录警告。

MuseCoco 生成 MIDI 后，立即把速度统一到计划 BPM：

```powershell
D:\conda\python.exe -m stage1_story_agent normalize-tempo --input-midi ".\musecoco_outputs\motif_01.mid" --content-plan ".\stage1_story_agent\outputs\story-001-audit\content_plan.json" --output-midi ".\musecoco_outputs\motif_01.tempo-normalized.mid"
```

该命令不需要 DeepSeek API Key。它读取 `content_plan.json` 中的 `global.tempo_bpm`，覆盖 MIDI 内全部速度变化，并在第 0 tick 写入目标速度。未指定 `--output-midi` 时，默认在输入文件旁生成 `<原文件名>.tempo-normalized.mid`。如输出已存在，需显式加入 `--force`。

心跳鼓轨由 Stage 2 根据 `stage2_plan.json` 生成，并在 MIDI-GPT 处理期间作为完整 MIDI 的组成轨道进行保护。Stage 3 直接对这份完整 MIDI 统一分配音源、渲染和混音；不要把实验性的 `render-heartbeat` 命令作为正式流程，也不要在 MIDI-GPT 完成后重新生成心跳事件。

如需单独执行严格调性修正：

```powershell
D:\conda\python.exe -m stage1_story_agent normalize-key `
  --input-midi ".\musecoco_outputs\motif_01.tempo-normalized.mid" `
  --content-plan ".\stage1_story_agent\outputs\story-001-audit\content_plan.json" `
  --output-midi ".\musecoco_outputs\motif_01.final.mid"
```

该独立命令读取 `global.global_tonality`，自动检测源调并强制修正主音，检测含糊或移调越界时拒绝输出。完整 Stage 1 默认使用 `--tonality-policy soft`，遇到这些调性不确定情况会保留速度归一化 MIDI、写入审计并继续；若源 MIDI 的源调已由人工确认，可向独立命令同时传入 `--source-tonic` 与 `--source-mode`。

成功后产生四个独立交付目录：

```text
stage1_story_agent\outputs\story-001-musecoco\musecoco_plan.json
stage1_story_agent\outputs\story-001-heartbeat\heartbeat_processing_plan.json
stage1_story_agent\outputs\story-001-stage2\stage2_plan.json
stage1_story_agent\outputs\story-001-audit\content_plan.json
```

- MuseCoco 目录包含主题家族、12 属性文本、速度归一化目标，以及以下直接编码文件：

```text
predict.json
predict_index.json
direct_attribute_labels.json
predict_attributes.json
encoding_manifest.json
```

- `predict_attributes.json` 是严格按 MuseCoco 官方 `att_key.json` 排列的 60 分类头 one-hot；
- `direct_attribute_labels.json` 保存 12 类组合标签和每个主题的 63 个最终属性 Token；
- 已选乐器/流派编码为 `[1,0,0]`，同字段未选项硬编码为 `[0,1,0]`，不会使用 NA；
- 当前不会伪造概率，也不会直接生成 `infer_test.bin`；后续需要 WSL 适配器完成 JSON 到 pickle 的环境边界转换；
- heartbeat 目录保存心跳规划的兼容/审计视图；正式鼓轨执行应迁移到 Stage 2，由 Stage 2 消费 `stage2_plan.json` 并生成整曲心跳鼓轨；
- stage2 目录包含段落长度、鼓轨节奏型、逐段 BPM 和 MIDI-GPT 保护/编辑范围；Stage 2 据此生成并保护心跳鼓轨，不把心音 WAV 交给 MIDI-GPT；
- audit 目录只保存完整计划、模型原始响应和哈希。

给予 MuseCoco 的自然语言文本位于：

```text
theme_families[*].musecoco_text
```

同一对象的 `musecoco_text_style` 应为 `official-template-aligned-v1`；`musecoco_attribute_targets` 保存与文本逐项对应的 12 类离散属性，便于检查而无需反向解析英文。

用 PowerShell 查看全部 MuseCoco 文本：

```powershell
$plan = Get-Content ".\stage1_story_agent\outputs\story-001-musecoco\musecoco_plan.json" -Raw -Encoding UTF8 | ConvertFrom-Json; $plan.theme_families | Select-Object theme_family_id, musecoco_text
```

## 输入与输出

默认示例输入：

```text
stage1_story_agent\examples\story_input.example.json
```

可以复制该文件并修改：

- `story_id`：本次故事 ID；
- `story_text`：需要分析的完整故事；
- `total_bars`：全曲总小节数；
- `target_form_sections`：期望的曲式段落数，可设为 `null` 让模型判断；
- BPM、拍号、调式和主音允许范围。

成功运行按消费者分开生成：

```text
*-musecoco/musecoco_plan.json                  MuseCoco 专用
*-musecoco/predict.json                        官方自然文本输入格式
*-musecoco/predict_attributes.json             官方60头确定性编码
*-musecoco/direct_attribute_labels.json        12类组合编码与Token
*-musecoco/predict_index.json                   主题家族索引
*-musecoco/encoding_manifest.json               编码契约与文件哈希
*-heartbeat/heartbeat_processing_plan.json     心跳规划兼容/审计视图（待迁移）
*-stage2/stage2_plan.json                       第二阶段鼓轨生成与MIDI-GPT编排输入
*-audit/content_plan.json                       完整审计视图
*-audit/raw_response.json                       DeepSeek 结构化草稿
*-audit/run_manifest.json                       所有交付文件哈希
```

`variation_tasks` 是项目级 MIDI-GPT 后续任务，不是 MIDI-GPT 官方请求。当前 `musecoco_requests` 固定为空；本模块不会直接运行 MuseCoco 或生成 MIDI。

也可以不读取计划文件，直接指定速度：

```powershell
D:\conda\python.exe -m stage1_story_agent normalize-tempo --input-midi ".\musecoco_outputs\motif_01.mid" --target-bpm 96
```

速度调整只改 Standard MIDI File 的 `Set Tempo` 元事件，不改音符的拍内 tick 位置，也不做量化或音频时间拉伸。当前支持 PPQ 计时的 MIDI format 0/1；format 2 和 SMPTE time division 会被拒绝。每个 MuseCoco 动机 MIDI 都应分别执行一次，再交给第二阶段装配器。

## 常见问题

### PowerShell 出现 `>>`

这表示上一条命令尚未结束。按 `Ctrl+C` 回到 `PS ...>`，然后重新复制本指南中的单行命令。不要把测试命令和 Agent 命令粘贴成一行。

### 提示输出目录已经存在

命令末尾加入 `--force`。程序会先备份旧目录，发布失败时恢复旧内容。

### 提示缺少 `DEEPSEEK_API_KEY`

确认 `.env` 位于项目根目录：

```text
<repository-root>\.env
```

并确认内容使用以下格式，没有中文引号：

```dotenv
DEEPSEEK_API_KEY=真实Key
```

不要把 `.env`、真实 Key 或 `raw_response.json` 发送给无关人员。`.env` 已被 `.gitignore` 排除。

### 如何判断运行成功

命令退出码为 `0`，且 audit 输出目录同时包含 `content_plan.json`、`raw_response.json`、`form_scale_decision.json` 和 `run_manifest.json`。`form_scale_decision.json` 记录段落数量、总小节数及主题复用蓝图；打开 `content_plan.json` 后，应能看到详细的 `form_plan`、`theme_families`、`variation_tasks` 和 `provenance`。
